# Local HotCRP development

This checkout runs a test conference on your Mac. Edit the source here, refresh the browser, and commit changes to your fork. All runtime data stays in ignored local directories.

## Open the conference

- Conference: http://127.0.0.1:8080/
- Captured email: http://127.0.0.1:8025/
- Passwords: `var/local/accounts.json` (local only, readable by your macOS account).

| Account | Purpose |
| --- | --- |
| `admin@hotcrp.localhost` | Conference chair and administrator |
| `author@hotcrp.localhost` | Author of sample paper 1 |
| `reviewer@hotcrp.localhost` | Assigned reviewer with a submitted review |
| `outsider@hotcrp.localhost` | Unassigned user for checking permissions |

Passwords are randomly generated and are excluded from Git. Use the matching password from `var/local/accounts.json`. These synthetic addresses use the reserved `.localhost` domain. HotCRP suppresses email to `.test` and example domains, so those cannot exercise the mail workflow.

The conference accepts submissions through December 31, 2027, at 11:59 PM America/New_York. Reviews are anonymous, reviewing is open, and authors cannot see reviews until you release them in Settings. Paper 1 contains an upstream sample PDF and a synthetic review.

## Start and stop

Run from the repository root:

```sh
python3 local-dev/manage.py start
python3 local-dev/manage.py status
python3 local-dev/manage.py stop
python3 local-dev/manage.py restart
```

Services run as your macOS user and do not automatically restart at login. Start them again after reboot. Do not also start the global Homebrew nginx, PHP, or Mailpit services on the same ports.

Nginx listens on `127.0.0.1:8080`; Mailpit listens on `127.0.0.1:8025` and SMTP port `127.0.0.1:1025`. MariaDB and PHP-FPM use private Unix sockets. Nginx routes application requests through `index.php`; only images, scripts, and stylesheets are served directly. PHP checks edited source on every request. Runtime configuration is regenerated by `start`; edit `local-dev/manage.py` to make persistent changes to it.

Logs, sessions, the database, captured email, backups, and generated service configuration are under `var/local/`. Database credentials are in `conf/options.php`. Both directories are ignored by Git. No real email is delivered: PHP uses Mailpit's sendmail replacement, and Mailpit has no relay configured.

## Edit and save code

```sh
git switch -c feature/my-change
# Edit PHP, JavaScript, CSS, or other source files, then refresh the browser.
python3 local-dev/smoke.py
git diff
git add path/to/changed-file
git commit -m "Describe the behavior change"
git push -u origin HEAD
```

Use a hard browser refresh when editing JavaScript or CSS. PHP changes require no build step. Advanced frontend assets may have their own build instructions under `devel/`.

`origin` is your fork, https://github.com/huaxu7000/hotcrp. `upstream` is https://github.com/kohler/hotcrp. The initial setup lives on branch `local-development`.

Before incorporating official updates, commit your work and back up the database:

```sh
python3 local-dev/manage.py backup
git fetch upstream
git merge upstream/master
python3 local-dev/smoke.py
git push
```

HotCRP can update its database schema when newer code runs. Restoring older code may also require restoring its matching database backup. Keep any custom database migrations in `local-dev/migrations/` and record their application order; do not modify the live schema without a reproducible script.

## Verify changes

```sh
python3 local-dev/smoke.py
python3 local-dev/manage.py php batch/checkinvariants.php --verbose
python3 local-dev/manage.py php -l path/to/changed.php
```

The smoke check signs in as the sample users, checks paper and review visibility, downloads the PDF and compares its bytes, requests a password-reset email into Mailpit, and verifies private files are not served. It expects the baseline accounts and sample paper to remain present. It adds a captured reset message but does not change passwords.

Use `manage.py php` for PHP commands so they use this installation's socket and configuration. Upstream's full test suite requires separate test databases; follow `.github/workflows/tests.yml`, retaining this installation's custom socket configuration. Never point upstream tests at `hotcrp_local`.

## Back up and reset

```sh
python3 local-dev/manage.py backup
python3 local-dev/manage.py restore /absolute/path/to/backup.sql
python3 local-dev/manage.py reset
```

`backup` writes a timestamped SQL file under `var/local/backups/`. `restore` and `reset` stop web access, automatically back up the current database, restore the selected snapshot, and restart web access. `reset` restores `var/local/backups/clean-test.sql`, with four accounts, paper 1, and its review. It replaces subsequent conference changes. Captured mail and local session files are retained.

Paper PDFs are stored in the database, so SQL backups include them. Back up `conf/options.php` and `var/local/accounts.json` separately to private storage if you need to recover onto another machine. GitHub contains code, not these credentials or conference backups. A database restored from another installation may have different account passwords from this Mac's accounts file.

To intentionally replace the baseline later, copy a verified new backup over `var/local/backups/clean-test.sql`. Keep the old snapshot if you may need it.

## Recreate on a fresh Mac

Install Homebrew and Git, clone your fork, then run:

```sh
brew install php nginx mariadb poppler mailpit
python3 local-dev/manage.py init
python3 local-dev/manage.py php batch/settings.php save local-dev/settings.json
python3 local-dev/manage.py php local-dev/seed.php
python3 local-dev/manage.py backup
```

Copy that final verified backup to `var/local/backups/clean-test.sql` to enable `reset`. Seeding refuses to run over existing accounts. The stack requires Python 3 as provided by this Mac's developer tools. The paths are generated for the current checkout location; stop the stack before moving it, then run `start` from its new location. Keep `conf/options.php` and all database files together.

## Visual theme

`stylesheets/aitcc-theme.css` adds an AITCC-inspired navy, blue, warm-white, and peach palette, refreshed controls, and responsive dashboard panels. It uses system fonts and does not load third-party assets. It changes presentation only; upstream PHP, JavaScript, forms, roles, and conference policies are unchanged.

The local configuration enables it with:

```php
$Opt["stylesheets"][] = "stylesheets/aitcc-theme.css";
```

Remove that entry from `conf/options.php` to return to upstream styling, then refresh the browser. The same entry in `local-dev/manage.py` enables the theme on fresh installations. The stylesheet preserves upstream print layouts and uses a dark palette when your system prefers dark mode. Adjust the palette tokens at the top of the stylesheet to customize it further.
